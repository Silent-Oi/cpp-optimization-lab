# 技术路线

本路线围绕 **稀疏矩阵与高性能计算**、**路径追踪与图形渲染** 两个能力方向展开。

- **中期作品：稀疏 Poisson 求解器**
- **最终整合作品：高性能 CPU 路径追踪器**

各项目通过具体程序承接前一阶段的知识，逐步建立独立实现、解释和扩展程序的能力。

Project01 已于 2026-10-09 正式结束，近期顺序为 Project02 CPU/CUDA 热扩散 → Project03 稀疏求解器。后续图形阶段沿同一个渲染器持续演进；基础图形实践可以在数值项目形成稳定版本后开始，不以完成全部数值性能优化为前提。

## 路线总览（暂定）

| 项目 | 目标 | 主要新增能力 | 通向下一步的作用 |
|---|---|---|---|
| Project01 — Batch Oscillator | 百万级欠阻尼振子更新与相空间星云 | 连续内存、AoS/SoA、benchmark、自动向量化、CPU 像素绘制 | 建立第一个完整的计算—优化—显示闭环 |
| Project02 — CPU/CUDA Heat Equation | CPU/CUDA 二维热扩散模拟与温度场显示 | 规则网格、stencil、边界条件、稳定性、双缓冲、CUDA 执行与内存模型 | 从独立更新进入邻域计算，建立首个 GPU 计算实现 |
| Project03 — Sparse Poisson Solver | CPU 稀疏 Poisson 求解器与 CUDA 迭代求解 | CSR、matrix-free、SpMV、CG、残差与并行归约 | **完成中期作品** |
| Project04 — Basic CPU Ray Tracer | 能输出图像的基础 CPU 光线追踪器 | 向量几何、相机、光线求交、材质、图像缓冲 | 建立最终项目的正确渲染基线 |
| Project05 — Monte Carlo Rendering | 可渐进收敛的 CPU/CUDA 采样渲染器 | 随机数、统计误差、像素采样与累积 | 从确定性光追进入路径追踪 |
| Project06 — Spatial Hierarchy | 为已有渲染器加入 BVH | 包围盒、树构建、CPU/GPU 遍历与数据布局 | 解决复杂场景的求交规模问题 |
| Project07 — CPU Path Tracer | 多线程高性能 CPU 路径追踪器 | 三角形网格、BVH、随机反弹、任务调度、综合性能分析 | **完成最终整合作品** |

## 第一段：通向稀疏矩阵

### Project01 — 批量欠阻尼振子

实现大量独立状态的连续更新，理解连续内存、AoS/SoA、自动向量化、多线程与 CPU 像素绘制。

已完成 AoS/SoA、终止更新、自动向量化、简单多线程与相空间显示，并保存五组性能实验。学习项目正式结束；验证范围及显示状态等已知问题见[项目评价](../Project01_batch_oscillator/docs/project_evaluation.md)。CUDA 在 Project02 引入。
[Project01 — roadmap.md](../Project01_batch_oscillator/docs/roadmap.md)


### Project02 — CPU/CUDA 二维热方程

前四阶段已完成。CUDA 后端已能在显存中连续推进温度场，并已与 CPU 差分结果逐点对照。第五阶段分析 CPU/GPU 执行成本，并依据测量结果选择优化方向。具体安排见[六阶段技术路线](../Project02_heat_equation/docs/roadmap.md)。

把独立元素更新推进到每个网格点依赖邻居的计算。单线程阶段建立明确的状态与接口约束、时间层存储和规则更新循环；第二阶段分析数值误差、数据复用及并行同步成本，随后加入显示与 CUDA 后端。最终结合精度、数据移动和执行成本评价计算方案。

重点理解线程与网格点的对应、设备内存生命周期、同步、连续访问，以及计算与数据传输各自的成本。优化以实际观察为依据；shared memory 等手段按需要引入。

[Project02 — 项目计划](../Project02_heat_equation/README.md)

### Project03 — 稀疏 Poisson 求解器

把规则网格离散写成线性系统，完成 CSR、SpMV、共轭梯度法、简单预条件和 matrix-free 版本，形成中期的稀疏数值求解作品。

通过热扩散稳态与 Laplace/Poisson 问题的关系承接上一项目。先在 CPU 上验证边界处理、残差和解误差，观察网格加密与条件数对收敛的影响。自主实现核心后，与成熟数值库对照。

CUDA 是本项目的正式阶段。先把 CSR 矩阵向量乘法（SpMV）移到 GPU，与 CPU 逐项对照，分析按列索引间接读取向量带来的访问成本。随后将 CG 的向量更新和点积归约接入 GPU 迭代，用相同的收敛准则比较最终残差、解误差和求解时间。

## 第二段：通向 CPU 路径追踪

Project04～07 是同一个渲染器的连续技术阶段，复用已有实现并保留可比较的阶段成果。具体深度随实践和外部技术反馈调整。

### Project04 — 基础 CPU 光线追踪器

先做正确图像，不急着优化。建立相机、光线、几何求交、材质和图像输出。

### Project05 — Monte Carlo 渲染

在 P4 的 CPU 图像基础上加入随机采样和渐进累积，从像素采样开始建立 CUDA 渲染后端。用相同场景与每像素样本数，对照 CPU/GPU 的图像收敛和渲染时间。

### Project06 — 空间层次结构

在已有渲染器中实现 BVH，区分构建与遍历成本。将同一棵树用于 CPU 和 CUDA 求交，考察节点布局、访存及相邻线程沿不同分支遍历时的执行效率。

### Project07 — 高性能 CPU 路径追踪器

整合三角形网格、BVH、随机采样、多线程和性能分析，完成高性能 CPU 路径追踪器。沿用已有 CUDA 后端，在代表性场景中比较两种后端的渲染成本。

### 实时图形补充

探索实时渲染时，增加一个小型 GPU 网格查看器，覆盖相机、三角网格、深度测试、shader、基本材质与图形调试。选择一种图形 API 完成实践；CUDA 计算与 CPU 路径追踪不能替代这一部分。该扩展根据方向选择安排，不增加为所有后续项目的前置条件。

## 贯穿项目的工程能力

- 在实际模块中练习 C++ 所有权、RAII、容器与对象生命周期、接口约束和数据结构。
- 逐步完成 Linux 下的构建与调试，学习定位越界、数值异常、并发错误和性能热点。
- 对核心计算保留独立验证依据，能说明误差与适用范围。
- CPU/GPU 比较保持相同问题和明确的精度要求，分别说明核心执行、数据传输和端到端成本。
- 每个稳定版本能够构建、运行和演示，并能解释关键设计；文档规模以支持复现和理解为限。
