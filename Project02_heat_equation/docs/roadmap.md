# Project02 — 二维热扩散技术路线

## 目标与当前状态

实现矩形区域上的二维热扩散模拟器，包含 CPU 求解、数值误差分析、温度场显示和 CUDA 后端。基础模型采用均匀材料、常数热扩散系数、无内部热源及固定温度边界；交互模式额外施加局部温度增量。

前三阶段已完成：具备 CPU 五点差分单线程与多线程推进、单正弦模态解析参考、数值与性能实验，以及带鼠标单点加热／冷却的温度场显示。当前推进 CUDA 基础实现与验证。

## 路线位置与设计依据

本项目从 Project01 的独立状态更新进入具有空间依赖的场计算。新增知识包括有限差分、初始与边界条件、稳定性、收敛误差、邻域数据复用和并行时间层同步。热扩散的稳态问题为 Project03 的 Laplace/Poisson 离散与稀疏线性系统提供背景。

数值方法采用时间前向 Euler、空间二阶中心差分。该格式结构清楚，便于分析误差，也便于在 CPU 与 GPU 上实现相同计算。其主要代价是显式稳定条件限制时间步：网格细化不仅增加节点数，也增加推进到相同物理时刻所需的步数。因此，最终需要同时评价计算精度与求解成本。

性能设计围绕三个问题展开：每个时间层需要保留什么数据，邻近更新能复用哪些数据，以及并行任务何时必须同步。缓冲区管理、循环组织、向量化和任务划分是解决这些问题的手段，具体取舍由数据依赖、工作集和执行成本决定。

## 1. 物理模型与单线程求解器

从热量守恒与导热定律建立热方程，明确热扩散系数、区域尺寸、网格间距、初始条件和边界条件的含义。使用与边界相容的单正弦模态建立解析参考。

CPU 求解器采用连续存储的二维温度网格，提供初始化、单步与多步推进。实现设计覆盖以下职责：

- **状态与接口：** 明确网格节点与物理坐标的对应、数组长度约束、时间步和步数的语义。物理参数、网格描述与随时间变化的温度保持清楚的职责划分。
- **时间层与资源：** 旧温度在一轮推进中保持只读，新温度写入另一缓冲区。缓冲区跨时间步复用，两份缓冲区均维持正确边界，交换后得到完整的新状态。
- **计算与访问：** 沿连续方向扫描内部节点，利用相邻点和相邻行的数据复用；将时间推进期间不变的计算与逐点运算分开，使热循环保持规则。
- **编译器执行：** 结合向量化诊断检查循环依赖、访问方式和别名约束，确认实际生成代码。浮点表达式调整须保持约定的误差要求。

基础单线程版本由这些设计共同构成。对于单一温度场，连续数组是起点；是否需要改变行布局、增加对齐或引入分块，应由后续访问分析决定。

**阶段成果：** 能在明确的边界与稳定时间步下完成 CPU 单步和多步推进，具有清楚的资源生命周期、规则的更新循环以及解析参考对照入口。

## 2. 数值实验、数据分析与 CPU 并行

### 实验程序的组织

实验程序围绕“用例配置 → 单次运行 → 结果记录 → 参数扫描与汇总”组织。配置描述物理问题、离散参数和求解方式；单次运行负责建立状态并完成计算；误差或计时指标形成明确的结果数据；输出与绘图消费结果，不承担求解职责。

先完成一个误差实验用例，再通过参数扫描检验接口是否便于扩展。误差实验与性能实验复用适合的配置、状态准备和结果输出方式，各自保留所需的参考解、误差计算或计时流程。出现第二种实际用途时再提取共同部分，使复用来自明确的数据流与职责，而不是预先构建通用实验框架。

设计的检验方式是：新增一个网格规模、一种指标或一个求解后端时，能够指出应修改的局部，并保持求解器、实验流程和展示之间的边界清楚。

### 数值误差与参数选择

开展[误差实验](../benchmarks/误差实验.md)，比较稳定条件内外的行为，分析时间与空间离散误差，并选择后续计算参数。网格和时间步比较保持相同物理区域、最终时刻与边界条件。分别考察误差来源及相互影响，避免把特定正弦模态上的误差抵消视为普遍精度保证。

### 数据访问与成本分析

从单点更新逐步扩展到一次完整求解，建立与实际实现相符的成本模型：

- **工作量与容量：** 统计每个内部节点的运算、逻辑读写与两份温度数组的存储量，再结合内部节点数和时间步数计算总工作量。区分固定步数与推进到固定物理时刻的成本。
- **数据复用与流量：** 根据连续行扫描、缓存容量和并行分区估计数据复用，区分源码中的数组访问次数、缓存层级间传输量和 DRAM 流量；对不能确定的缓存行为给出有假设的估计范围。
- **硬件约束与预测：** 在明确数据流量层级后估算算术强度，结合对应带宽与计算吞吐上限判断潜在限制，给出理想耗时下界及规模变化的预期。硬件峰值作为上限参考，实际可达到的性能由后续测量校准。
- **预测与解释：** 在计时前说明网格细化、步数增加和线程数变化预计会如何影响成本，再用实测差异检查缓存复用、带宽、线程启动及同步等假设。

连续行扫描已有空间复用；分析应进一步判断所需行数据是否能驻留缓存，以及并行分区会怎样改变复用。缓存分块、行填充等布局调整依据相关限制选择。将误差实验中的参数选择与总工作量联系起来，评价达到所需精度的计算成本。

### 多线程实现与实验

提供独立的 parallel 求解入口，与单线程 `solve` 使用相同离散规则、输入与精度。初始分工采用连续行区间，线程读取同一旧时间层并写入互不重叠的输出区域；所有区域完成后才交换时间层。线程生命周期、任务规模和每步同步是主要设计问题。

先对照数值结果，再通过规模与线程数实验分析启动成本、同步开销、负载分配及带宽限制。测量使用 Release，排除初始化和结果校验，保留求解调用实际承担的资源管理与同步成本。主要指标为每个内部节点每步耗时或节点更新吞吐，结合总耗时解释结果。

**阶段成果：** 形成职责清楚、可扩展用例与指标的实验程序，得到有误差依据的参数选择、具有明确假设的性能预测，以及通过正确性对照的多线程实现。能够解释预测与实测的差异，并为后续 CPU/GPU 比较复用实验组织与成本分析方法。

## 3. 温度场显示与交互

沿用 Project01 的 CPU 像素缓冲与 RGFW 窗口方案，从静态温度图逐步接入时间推进和交互：

1. **静态温度图：** 将温度映射为固定色标下的 RGBA 像素，先使用单正弦场检查空间方向与颜色分布。明确网格坐标与窗口像素的对应关系，使网格分辨率和显示尺寸可以独立设置。
2. **动态扩散与控制：** 按稳定的固定物理时间步推进，显示刷新读取最新温度。支持暂停、单步与恢复初始温度场；使用固定色标观察温度幅度的实际衰减。
3. **局部温度交互：** 鼠标映射到一个内部节点，左右键分别施加正负温度增量。增量按当前批次的模拟时间计算，采用单位受热体积的简化约定。绘制过程只读取温度，留白与固定边界不接受画笔，暂停时停止注热。

**收尾状态（2026-10-30）：** 上述功能已实现，Release 构建及现有求解器测试通过；窗口显示与鼠标交互已有人工运行反馈。当前按帧集中注热再扩散，结果可能受显示帧分组影响；重置保留不足一个物理时间步的计时余量。单节点交互构成本阶段的完成范围，圆形作用区域和逐步热源作为后续扩展。运行方式与限制见[项目说明](../README.md#运行与交互)。

**阶段成果：** 可运行和控制二维温度场显示，能够观察局部温度变化后的扩散、边界影响与趋向稳态的过程；计算、显示和输入职责清楚，为后续更换计算后端保留接口边界。

## 4. CUDA 基础实现

在 CPU 数值结果可信后接入 CUDA，统一构建 CPU 与 CUDA 实现，保留 CPU 求解器用于数值对照。将网格点映射到 GPU 线程，采用全局内存和设备双缓冲实现相同更新。处理边界线程、设备资源生命周期、kernel 时间层依赖、同步与错误检查。

CPU/GPU 初始比较保持相同精度，在相同物理时刻对照结果。温度数据在连续推进期间驻留设备，按显示或验证需求传回。

**阶段成果：** 具有正确的 GPU 后端，能够解释线程映射、数据驻留及各时间层之间的执行关系。

## 5. CPU/GPU 执行成本与瓶颈优化

分别测量 kernel、数据传输和端到端成本，正确处理异步执行。比较相同问题、精度与工作量下的 CPU/GPU 表现，结合 profiling 确定一个主要瓶颈并实施改进。

候选方向包括线程块形状、连续内存访问、传输频率和邻域数据复用；shared memory 的收益需与加载、同步及资源占用成本一起判断。精度或数值方法变化另行评价，避免与硬件加速混淆。

**阶段成果：** 得到有适用范围的 CPU/GPU 性能结论，能够用瓶颈证据解释一次优化的收益或限制。

## 6. 稳定版本与后续衔接

整理构建、运行示例、数值结果和性能结论，明确模型与适用范围。保持网格、计算后端、实验和显示之间的职责清楚。

从固定边界下的稳态出发，说明时间推进到稳态与直接求解稳态方程的联系，建立网格邻居关系与稀疏系数矩阵的对应。

**阶段成果：** 形成可运行、可验证、可演示的 CPU/CUDA 热扩散程序，并为 Project03 提供网格表示、边界处理和数值验证基础。
