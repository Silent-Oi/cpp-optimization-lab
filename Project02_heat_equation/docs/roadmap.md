# Project02 — 二维热扩散技术路线

## 目标与当前状态

实现矩形区域上的二维热扩散模拟器，包含 CPU 求解、数值误差分析、温度场显示和 CUDA 后端。模型采用均匀材料、常数热扩散系数、无内部热源及固定温度边界。

当前已实现 CPU 五点差分单步/多步更新和单正弦模态解析参考，正在完善第一阶段的单线程求解器。数值收敛和并行性能尚待验证。

## 路线位置与设计依据

本项目从 Project01 的独立状态更新进入具有空间依赖的场计算。新增知识包括有限差分、初始与边界条件、稳定性、收敛误差、邻域数据复用和并行时间层同步。热扩散的稳态问题为 Project03 的 Laplace/Poisson 离散与稀疏线性系统提供背景。

数值方法采用时间前向 Euler、空间二阶中心差分。该格式结构清楚，便于分析误差，也便于在 CPU 与 GPU 上实现相同计算。其主要代价是显式稳定条件限制时间步：网格细化不仅增加节点数，也增加推进到相同物理时刻所需的步数。因此，最终需要同时评价计算精度与求解成本。

性能设计围绕三个问题展开：每个时间层需要保留什么数据，邻近更新能复用哪些数据，以及并行任务何时必须同步。缓冲区管理、循环组织、向量化和任务划分是解决这些问题的手段，具体取舍由数据依赖、工作集和执行成本决定。

## 1. 物理模型与单线程求解器

从热量守恒与导热定律建立热方程，明确热扩散系数、区域尺寸、网格间距、初始条件和边界条件的含义。使用与边界相容的单正弦模态建立解析参考。

CPU 求解器采用连续存储的二维温度网格，提供初始化、单步与多步推进。实现设计覆盖以下职责：

- **状态与接口：** 明确网格节点与物理坐标的对应、数组长度约束、时间步和步数的语义。物理参数、网格描述与随时间变化的温度保持清楚的职责划分。
- **时间层与资源：** 旧温度在一轮推进中保持只读，新温度写入另一缓冲区。缓冲区跨时间步复用，两份缓冲区均维持正确边界，交换后得到完整的新状态。
- **计算与访问：** 沿连续方向扫描内部节点，利用相邻点和相邻行的数据复用；将时间推进期间不变的计算与逐点运算分开，使热循环保持规则。
- **编译器执行：** 结合向量化诊断检查循环依赖、访问方式和别名约束，确认实际生成代码。浮点表达式调整须保持约定的误差要求。

基础单线程版本由这些设计共同构成。对于单一温度场，连续数组是起点；是否需要改变行布局、增加对齐或引入分块，应由后续访问分析决定。

**阶段成果：** 能在明确的边界与稳定时间步下完成 CPU 单步和多步推进，具有清楚的资源生命周期、规则的更新循环以及解析参考对照入口。

## 2. 数值实验、数据分析与 CPU 并行

### 数值误差与参数选择

开展[误差实验](../benchmarks/误差实验.md)，比较稳定条件内外的行为，分析时间与空间离散误差，并选择后续计算参数。网格和时间步比较保持相同物理区域、最终时刻与边界条件。分别考察误差来源及相互影响，避免把特定正弦模态上的误差抵消视为普遍精度保证。

### 数据访问与成本分析

建立与实际实现相符的成本模型：温度数组和辅助数据占用多少空间，一次内部节点更新需要哪些运算和逻辑访问，相邻更新如何复用数据。区分工作集容量、缓存层级间的数据流量和 DRAM 流量。

连续行扫描已有空间复用；分析应进一步判断所需行数据是否能驻留缓存，以及并行分区会怎样改变复用。缓存分块、行填充等布局调整仅在相关限制出现时选择，避免增加索引和管理成本却没有解决实际问题。

### 多线程实现与实验

提供独立的 parallel 求解入口，与单线程 `solve` 使用相同离散规则、输入与精度。初始分工采用连续行区间，线程读取同一旧时间层并写入互不重叠的输出区域；所有区域完成后才交换时间层。线程生命周期、任务规模和每步同步是主要设计问题。

先对照数值结果，再通过规模与线程数实验分析启动成本、同步开销、负载分配及带宽限制。测量使用 Release，排除初始化和结果校验，保留求解调用实际承担的资源管理与同步成本。主要指标为每个内部节点每步耗时或节点更新吞吐，结合总耗时解释结果。

**阶段成果：** 得到有误差依据的参数选择、可解释的数据访问模型，以及通过正确性对照的多线程实现和性能结论，为后续 CPU/GPU 比较提供可信基线。

## 3. 温度场显示

基于 CPU 像素缓冲与窗口层实现温度到颜色的映射、暂停、单步和重置。采用固定色标作为初始方案，保持不同时间与参数下的颜色含义一致。显示只读取温度，物理步长与显示刷新分离，重置覆盖完整仿真与显示状态。

**阶段成果：** 可以观察扩散、边界影响与趋向稳态的过程，并将计算结果和视觉现象对应起来。

## 4. CUDA 基础实现

在 CPU 数值结果可信后接入 CUDA，保留独立的 CPU 构建入口。将网格点映射到 GPU 线程，采用全局内存和设备双缓冲实现相同更新。处理边界线程、设备资源生命周期、kernel 时间层依赖、同步与错误检查。

CPU/GPU 初始比较保持相同精度，在相同物理时刻对照结果。温度数据在连续推进期间驻留设备，按显示或验证需求传回。

**阶段成果：** 具有正确的 GPU 后端，能够解释线程映射、数据驻留及各时间层之间的执行关系。

## 5. CPU/GPU 执行成本与瓶颈优化

分别测量 kernel、数据传输和端到端成本，正确处理异步执行。比较相同问题、精度与工作量下的 CPU/GPU 表现，结合 profiling 确定一个主要瓶颈并实施改进。

候选方向包括线程块形状、连续内存访问、传输频率和邻域数据复用；shared memory 的收益需与加载、同步及资源占用成本一起判断。精度或数值方法变化另行评价，避免与硬件加速混淆。

**阶段成果：** 得到有适用范围的 CPU/GPU 性能结论，能够用瓶颈证据解释一次优化的收益或限制。

## 6. 稳定版本与后续衔接

整理构建、运行示例、数值结果和性能结论，明确模型与适用范围。保持网格、计算后端、实验和显示之间的职责清楚。

从固定边界下的稳态出发，说明时间推进到稳态与直接求解稳态方程的联系，建立网格邻居关系与稀疏系数矩阵的对应。

**阶段成果：** 形成可运行、可验证、可演示的 CPU/CUDA 热扩散程序，并为 Project03 提供网格表示、边界处理和数值验证基础。
