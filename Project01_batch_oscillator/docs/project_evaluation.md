本次执行 MSVC x64 / Ninja Release 构建和 `oscillator_tests.exe`，均成功，测试退出码为 0。检查使用已有构建目录，不是全新环境的安装复现。未重新运行整套性能实验，未进行窗口交互验收或跨平台验证。

已有测试包含解析状态与一步转移对照、无阻尼情况、空批量、单元素与小批量更新。多线程测试以 16 个振子推进 16 步，逐元素比较 1、2、3 线程与单线程结果，3 线程覆盖了不能整除的区间分配。通过这些测试支持当前实现的基本正确性，不能代替所有参数和生命周期边界的验证。

五组性能实验分别涉及 AoS/SoA、AoS 对象大小、终止机制、向量化和多线程。计时排除了初始化、输入恢复和输出，包含预热、重复测量、均值/中位数、有限值检查及结果摘要消费，基本测量结构合理。多线程调用中的线程创建与等待被计入，体现该接口的实际调用成本。

结果解释需要保留以下边界：

- benchmark 内部的重复摘要检查主要确认同一路径的重复一致性，不等于所有实现之间的逐元素正确性证明；多线程另有独立对照测试。
- 终止版本减少实际执行的更新次数，且使用能量阈值近似；其耗时不能当成相同计算量下的纯实现加速。
- 多线程实现让各线程在自己的分块上完成全部时间步。与全批量逐步扫描相比，缓存访问顺序也发生变化，收益不能全部归因于增加 CPU 核心。
- 当前多线程 CSV 输出已包含 `threads`；历史无该字段的结果仍不能反推线程配置。构建配置、编译选项与硬件信息尚未随每份 CSV 完整保存，不能由已有文件确认完整的线程数扩展性曲线或跨机器性能结论。

## 已知问题与局限

1. **终止状态未传递到绘制筛选。** 更新器会从 `active_indices` 删除低能量振子，渲染器仍遍历全部振子。因此，已停止更新的点仍参与像素累加，不能保证“退出绘制后仅让旧拖尾自然结束”。这是静态代码确认的行为；本次未重新观察窗口效果。
2. **重置没有重置完整显示状态。** `r` 键恢复振子数组，但复用原来的渲染器与像素缓冲，没有清空拖尾列表和寿命状态。重置后可能短暂保留此前轨迹。
3. **输入规模显示存在错误。** 通用 `measure` 使用 `N * sizeof(Batch) * 8`，部分输出使用 `N * sizeof(SoABatch)`；容器对象大小不等于堆上数组数据大小。这影响内存规模说明，不直接改变计时结果，不宜据此判断缓存工作集。
4. **批量接口依赖调用者维持不变量。** SoA 的多个公开数组可独立修改长度，更新函数默认其长度一致；区间接口混用 `int` 与 `size_t`。工厂返回的当前规模数据满足使用条件，但接口不适合作为任意外部输入的稳健公共 API。
5. **测试覆盖仍有限。** 终止阈值、退出后的显示行为、多线程空批量/线程数大于元素数及非法参数等尚无完整回归覆盖。现有测试通过不能表述为这些边界都已验证。

以上作为结束版本的已知问题保留，不自动扩展为新的开发阶段。后续复用相关模块时，应针对复用场景处理；尤其不能直接把独立振子的多步分块推进照搬到有邻域依赖的网格计算。

## 总体结论

项目最有价值的部分是：同一数值问题有明确参考、不同数据布局和执行方式，并配有能够观察实际成本的测量工具。计算核心与性能实验的成熟度高于显示状态管理和公共接口约束。

以第一阶段数值计算与 CPU 优化作品衡量，项目主体已完成，具备继续进入二维热扩散项目的基础。正式结束表示本轮范围关闭，已知问题和未验证项按上述记录保留，不表示所有最初设想或所有工程边界均已完成。
