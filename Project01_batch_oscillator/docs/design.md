## 模型约定

线性黏性阻尼模型：

\[
m x'' + c x' + kx = 0
\]

使用：

\[
\omega=\sqrt{k/m},\qquad
\zeta=\frac{c}{2\sqrt{km}}
\]

得到一阶系统：

\[
\dot{x}=v,\qquad
\dot{v}=-2\zeta\omega v-\omega^2x
\]

第一版参数边界：

- `omega` 有限且严格大于零。
- `zeta` 有限，核心物理范围为 `0 < zeta < 1`。
- `zeta = 0` 仅用于无阻尼回归。
- 所有振子使用统一 `dt`，但可以拥有不同状态、`omega` 和 `zeta`。
- 第一版统一使用 `double`。

## 精确一步更新

对于参数不随时间变化的振子：

\[
y_{n+1}=M(\omega,\zeta,\Delta t)y_n,
\qquad y=[x,v]^T
\]

初始化阶段计算更新矩阵的四个系数，核心循环只进行两个线性组合。

选择这一方案的目的不是提前追求最快实现，而是：

- 使直接解析状态和多步更新具有相同物理模型。
- 使 AoS/SoA 对比不受不同积分误差干扰。
- 明确区分初始化成本和热循环成本。
- 为“更多预计算是否值得更多内存读取”提供后续实验入口。

## 正确性约定

按以下层次建立证据：

1. 无阻尼解析解和已有积分器的最低回归。
2. 阻尼解析状态在 `t = 0` 恢复初值。
3. 精确一步更新与解析状态一致。
4. 多步更新与直接计算终止时刻一致。
5. `zeta = 0` 退化为无阻尼模型。
6. 批量更新与逐个标量更新一致。
7. AoS、SoA 和可选并行版本在约定容差内一致。

连续阻尼模型的机械能应满足非增趋势，但数值检查仍需设置浮点容差，不能用逐步严格小于作为唯一正确性条件。

## 数据职责

### 状态

随时间变化：

- `position`
- `velocity`

### 原始只读参数

- `omega`
- `zeta`

### 派生更新参数

- 固定 `dt` 下精确一步矩阵的系数。

状态、原始参数和派生参数在概念上分开。M2 将它们组合在一个连续 AoS 元素中作为 baseline；M4 必须保持相同语义，只改变需要实验的数据布局。

## V1 可视化架构边界

规划中的依赖关系：

```text
oscillator_core
├── apps
├── tests
├── benchmark
└── oscillator_visualizer

oscillator_visualizer
├── 调用 oscillator_core
├── RGFW 窗口与事件
└── visualizer 自己的软件绘制代码
```

职责约定：

- `oscillator_core` 继续只保存物理模型、状态、参数和更新算法，不依赖 RGFW、窗口、颜色、像素、帧率或输入事件。
- `oscillator_visualizer` 直接调用现有 `make_OscillatorAoS_batch()`、`update_aos_batch_step()` 或 `update_aos_batch()`；不得复制振子公式或维护第二套更新算法。
- 抽样索引、屏幕坐标、颜色、RGBA 像素缓冲、交互状态和显示节奏全部属于 visualizer。
- 不为了可视化向 `state.h` 添加窗口、绘制、帧记录或 benchmark 展示类型。
- 只有实现阶段证明现有只读访问不足时，才讨论最小核心观察接口；当前不设计 snapshot 框架。
- RGFW 依赖和 implementation 只属于未来的 `oscillator_visualizer` target，implementation 只在一个翻译单元中实例化。
- 绘制、事件轮询、帧率限制、截图和交互不进入正式 benchmark 计时，visualizer 帧率不用于推断核心计算性能。
- AoS/SoA、自动向量化和线程扩展性继续由独立 benchmark 负责，visualizer 不承担布局性能实验。

## 振子点阵与数据映射

最终最小画面是实时振子点阵，而不是单振子动画：

- 屏幕使用规则网格，每个单元显示一个确定性抽样得到的振子。
- 单元中心代表平衡位置，光点的水平偏移代表 `position`。
- 颜色或亮度代表 `velocity` 的方向和大小；具体色值与缩放常量在实现阶段记录。
- 计算 batch 可以达到百万规模，显示数量根据窗口大小限制为数百至一千个代表样本。
- 抽样索引必须固定、可复现并均匀覆盖整个 batch，不能默认只显示前若干项。
- 抽样和坐标映射只改变展示密度与表示方式，不改变被展示状态的物理含义。

单振子画面只用于验证核心接入、尺度和时间推进，是进入点阵实现的中间步骤。

## 模拟时间与显示时间

V1 分别管理：

- 固定物理时间步 `dt`。
- 每次显示更新之间执行的模拟推进次数。
- 现实经过时间。
- 画面刷新帧率。

第一版可以从每帧推进固定步数开始，但 V1 完成前必须理解并记录固定时间步 accumulator 如何把现实时间转换为零次或多次固定 `dt` 推进。显示器刷新率不能静默改变模拟时间语义，也不能为了保持固定帧率修改核心物理公式。

## 最小交互与展示证据

V1 核心交互固定为：

- `Space`：暂停与继续。
- `Right Arrow`：暂停时执行一次固定时间步推进。
- `R`：按相同 seed、参数和规模恢复初始状态。
- `Escape`：退出。

项目正式运行展示素材计划放在 `docs/showcase/`，至少保留一张代表截图和一段 GIF 或短视频。`docs/diagrams/` 继续保存源码结构、数据流与实现思路图；`docs/learning_logs/<里程碑>/assets/` 继续保存手写推导、临时截图和学习过程证据。本次只记录位置决定，不创建目录或素材。

## V1 范围边界

V1 不引入 GUI 框架、字体系统、菜单、滑块、鼠标交互、多窗口、OpenGL、Vulkan、DirectX、shader 或 GPU 绘制，也不建立通用 renderer、scene、window wrapper 或图形抽象层。相空间轨迹、对比画面、曲线、额外颜色映射、复杂参数编辑和 GPU 绘制只有在振子点阵核心成果完成且仍有明确学习价值时，才作为条件扩展讨论。

## 性能主线的计划实现层次

1. 单个无阻尼参考与积分器。
2. 单个阻尼解析参考和一步更新。
3. 清晰的连续 AoS batch。
4. 只改变布局的 SoA 实验版本。
5. 满足进入条件时的简单并行版本。

这些层次不应被提前抽象成通用 ODE 框架。V1 是独立并行支线，不插入或重排这组性能实现层次。
