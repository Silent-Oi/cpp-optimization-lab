# Project01 关键设计

这里只记录会持续影响代码的决定，不记录待办事项、每日进度或实验报告。

## 1. 模型

使用一维线性黏性欠阻尼振子：

```text
x' = v
v' = -2 * zeta * omega * v - omega^2 * x
```

范围：

- `omega` 有限且大于零
- `0 < zeta < 1`
- `zeta = 0` 只用于无阻尼回归
- 统一 `dt`
- 每个振子可以拥有不同状态、`omega` 和 `zeta`
- 第一版使用 `double`

临界阻尼和过阻尼不属于核心范围。

## 2. 精确一步更新

固定参数和固定 `dt` 下，状态更新为常系数线性变换：

```text
x_next = a * x + b * v
v_next = c * x + d * v
```

`a, b, c, d` 在初始化时根据 `omega`、`zeta` 和 `dt` 计算。

这样做的原因：

- 多步更新可以直接对照解析状态。
- AoS / SoA 比较使用完全相同的物理与计算语义。
- 热循环没有 `sin`、`cos`、`exp`，适合研究数据布局和编译器优化。
- 初始化成本和更新成本明确分离。

## 3. 数据职责

随时间变化：

- `position`
- `velocity`

原始参数：

- `omega`
- `zeta`

固定 `dt` 的派生参数：

- `a`
- `b`
- `c`
- `d`

AoS baseline 把这些字段放在同一个振子元素中，优先保证语义直观和验证简单。

SoA 实验保持完全相同的字段与更新公式，只把各字段拆成连续数组。这样性能差异主要来自布局，而不是算法变化。

## 4. 程序边界

```text
oscillator_core  -> 模型、初始化和更新
tests            -> 防止结果写错
benchmark        -> 测量核心更新
visualizer       -> 调用核心更新并画出状态
```

- core 不依赖窗口、帧率、输入事件或图形库。
- benchmark 不包含初始化、复制、结果汇总和输出时间。
- visualizer 不复制第二套振子公式。
- 绘制性能不用于证明 AoS 或 SoA 的核心计算性能。

## 5. Benchmark

AoS 与 SoA 使用：

- 相同 `seed`
- 相同参数分布
- 相同 `dt`
- 相同初始状态
- 相同总更新语义

每个规模保留预热、重复测量和结果 checksum。测量只需要回答当前布局问题，不要求独立实验报告。

## 6. 相空间星云

相空间映射：

```text
screen_x <- position
screen_y <- velocity / omega
```

`velocity / omega` 与 `position` 具有相近尺度，更适合观察相轨迹。

显示层决定：

- 使用独立 visualizer target。
- 第一版使用 CPU RGBA 像素缓冲。
- 窗口与事件层使用轻量依赖 RGFW。
- 相空间范围由初始条件或固定参数决定，不逐帧自动缩放。
- 超出范围允许裁剪，不修改物理状态。
- 拖尾属于像素显示效果，不写入振子状态。
- visualizer 可以使用专门设计的确定性初始分布，以得到清楚的星云结构。
- 可视化规模与百万级 benchmark 规模分离。
